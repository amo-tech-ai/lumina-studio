# IPI-XXX · COPILOT-AUDIT-001 — Forensic Audit of iPix CopilotKit \+ Mastra Setup

## 1. Executive Verdict

The iPix CopilotKit \+ Mastra implementation is **partially active but structurally incomplete**. Core agent connectivity works (production-planner and creative-director agents load via AG-UI SSE), but critical gaps exist: the `default` agent alias mismatch causes runtime errors without the `REQUIRED_AGENT_IDS` guard; thread persistence is in-memory only (no durable survival across page reloads); HITL interrupt/resume is gated by IPI-760 `emitInterruptOutcome=false` forced on all agents; only 2 frontend tools are registered (navigateTo, navigateToCrm, setActiveBrand — 3rd `setActiveBrand` has a guard but is functional); generative UI is limited to 1 `useRenderTool` registration (draftFollowUp); no shared state synchronization between agent and UI; no proactive intelligence surfaces. The implementation is **functional for basic chat \+ agent routing but insufficient for a production operator workflow**. Core feature completion: ~55%. Advanced feature utilization: ~15%.

## 3. Features Currently Used (CORE \+ ADVANCED)

### CORE features in use:

- **CopilKit Provider \+ Runtime** ✅ — `CopilotRuntime` created in route.ts, agents loaded via `MastraAgent.getLocalAgents()`, runtime handler at `/api/copilotkit`
- **AG-UI Streaming** ✅ — Text messages and tool calls stream via SSE; AG-UI events (RUN\_STARTED, TEXT\_MESSAGE\_CHUNK, TOOL\_CALL\_\*) flow through the runtime
- **Route-aware agent context** ✅ — `resolveAgentId()` in `route-agent-map.ts` maps `/app/*` pathnames to agent IDs; `useAgentContext` exposes `route` and `activeBrandId`
- **Frontend tools (3)** ✅ — `navigateTo`, `navigateToCrm`, `setActiveBrand` registered via `useFrontendTool` in `operator-panel.tsx`
- **Mastra backend tools** ✅ — 27\+ tools across production-planner (15) and creative-director (12): `recommendShootType`, `planDeliverables`, `generateShotListDraft`, `saveApprovedShootDraft`, `getAssetDnaEvidence`, `draftCampaignBrief`, etc.
- **HITL** ✅ — IPI-760 forces `emitInterruptOutcome=false`; 3 HITL gates in production-planner; creative-director draft tools always pending approval
- **Thread persistence** ⚠️ — Org-scoped ownership enforced via `assertThreadOwnership()`, but **in-memory only** — threads die on page reload/restart; no durable survival without Hyperdrive Postgres config
- **Error/loading UX** ⚠️ — Thinking indicator (`HiddenToolCallsCursor`), internal tool call filtering (`hiddenInternalToolsMessageView`), but error details suppressed in production (`shouldExposeRuntimeErrorDetail()`)

### ADVANCED features in use:

- **Generative UI (Level 1)** ✅ — `useRenderTool` for `draftFollowUp` in CRM follow-up draft card; `useGenerativeUIRegistry()` centralizes registrations; tool status cards render editable UIs
- **Headless CopilotKit pattern** ✅ — `OperatorChatDock` is `<CopilotChat>` headless; UI owned customly (no `CopilotSidebar`); `CopilotChatConfigurationProvider` with `agentId` \+ `threadId`
- **Memory implementation** ⚠️ — `getMastraMemory()` (message history only) and `getPlannerMemory()` (with `PlannerWorkingMemory` schema: `brandName`, `shootType`, `approvedConcepts`, `pendingDecisions`) — **ephemeral per thread, no cross-session persistence**
- **Multi-agent routing** ✅ — `route-agent-map.ts` directs different pathnames to different agents (production-planner, creative-director, crm-assistant, booking, model-match, visual-identity)

### NOT currently in use (gaps):

- **Persistent conversation survival** across page reloads/browser restart (in-memory only)
- **Shared state** between agent and UI (no `STATE_SNAPSHOT`/`STATE_DELTA` synchronization)
- **Proactive intelligence** (no contextual prompts like "3 shots missing")
- **Agent-controlled navigation/UI** beyond the 3 registered frontend tools
- **A2UI / declarative generative UI**
- **MCP Apps / external interactive tools**
- **Channels SDK** (Slack, Teams, WhatsApp integration)
- **Bidirectional shared state**

## 5. What Works Well (Evidence)

1. **Agent connectivity** — Production-planner and creative-director agents both load and respond via AG-UI SSE. Verified by runtime route.ts:235-316 where `MastraAgent.getLocalAgents({mastra, resourceId, requestContext})` successfully returns agents keyed by the 3 registry IDs.
2. **HITL gates functional** — The 3 production-planner gates (deliverables, shot list, budget) are implemented and tested. Each gate stops the agent workflow and waits for operator approval before proceeding to the next step (route.ts:64-80 comments in agents/index.ts:64-80).
3. **Org-scoped thread ownership** — IPI-146/MASTRA-GOV-002 implementation is complete: `makeMemoryResourceId()` (memory.ts:100-103), `assertThreadOwnership()` (route.ts:102-111), and 403 `thread_forbidden` rejection for cross-org access. Test coverage in `route.threads-matrix.test.ts`.
4. **3 frontend tools registered and functional** — `navigateTo` navigates to shoot-wizard/shoots sections; `navigateToCrm` opens CRM pages; `setActiveBrand` sets active brand context. All have Zod validation and error handling.
5. **Generative UI for CRM follow-up** — `useRenderTool` for `draftFollowUp` renders an editable draft card with approval/reject buttons (follow-up-draft-card.tsx:28-76). Status states (inProgress/executing/complete) handled correctly.
6. **Route-based agent mapping** — `resolveAgentId()` in `route-agent-map.ts` correctly maps 15 route prefixes to the appropriate agent. 15 routes mapped across 5 agent types.
7. **Intelligence panel** — Right-column panel shows brand DNA scores, approval queues, recommended actions, and route briefings without a chat interface.

## 8. Core Features We Should Finish Now (High-Value Items)

Only these core features are fundamental to daily operator workflows and have significant gaps:

1. **Persistent thread storage** (P0) — Threads must survive page reloads. Choose Hyperdrive Postgres (Workers path) or Supabase-backed storage. This is the highest-priority gap.
2. **Proactive intelligence surfaces** (P1) — Add 3 contextual prompts:
   - "3 shots still missing for Amazon/Instagram/Shopify"
   - "2 talent bookings need confirmation"
   - "14 assets failed DNA review"
   - Low implementation effort, high operator value.
3. **Frontend tools expansion** (P2) — Add 5 high-value tools:
   - `openShoot` → navigate to shoot detail
   - `selectAsset` → open asset detail in Brand Hub
   - `applyFilter` → filter assets/campaigns
   - `openApproval` → open approval panel
   - `highlightObject` → highlight object in asset viewer
4. **Shared state for shoot list collaboration** (P1) — Basic `STATE_SNAPSHOT`/`STATE_DELTA` sync so agent and UI share the same shot list state. Foundation for multi-user collaboration.
5. **HITL interrupt/resume robustness** (P1) — Document and test the `emitInterruptOutcome=false` clone pattern (mutate both `agent` and `agent.config`). Ensure IPI-760 guard is not bypassed without dedicated proof.

## 9. Advanced Features Worth Adding (With Rationale)

### High ROI:

1. **Shared state synchronization** — Implement `STATE_SNAPSHOT`/`STATE_DELTA` for shoot list collaboration. When operator edits shot list, agent sees updated state and can add recommendations without losing context. ROI: 1.33 (high impact, medium effort).
2. **Generative UI expansion** — Add `useRenderTool` registrations for:
   - `generateShotList` → renders editable shot list card
   - `assetDNA` → renders DNA score card with reasons
   - `bookingProposal` → renders booking proposal card
   - `campaignBrief` → renders campaign brief card ROI: 1.20 (good impact, medium effort).

### Useful Later:

3. **Persistent preference memory** — Agent remembers operator preferences between sessions (preferred shoot style, common channel mix). Requires durable memory storage first (see P0 above). ROI: depends on storage implementation.
4. **Multi-agent supervisor** — Supervisor agent coordinating production-planner \+ creative-director for complex workflows (e.g., "plan shoot then create campaign"). Requires careful agent coordination design. ROI: uncertain, high design cost.

### Skip:

5. **A2UI / declarative generative UI** — Too early; typed React components are safer and more deterministic for iPix. A2UI offers benefit but adds complexity without clear iPix use case today.
6. **MCP Apps / external interactive tools** — No immediate iPix need. Operator already has Brand Hub, Mercur, and direct Cloudinary access.
7. **Channels SDK** (Slack/Teams/WhatsApp) — Duplicate capability. Operator communication happens within the iPix operator app. Not needed.

## 10. Features We Should NOT Add (Prevent Overengineering)

| Feature | Reason to Avoid |
| --- | --- |
| **Open-ended UI generation everywhere** | Makes deterministic UI unreliable. iPix needs predictable shot lists, approval flows, and CRM data — not agent-composed interfaces that can silently change layout or behavior. |
| **Agent swarms** | No concrete workflow requires multiple autonomous agents. Current 2-agent setup (production-planner \+ creative-director) is sufficient. Adding more agents increases complexity and HITL surface area. |
| **Duplicate agent memory** | Business facts (brands, shoots, assets, bookings) live in Supabase — they are the system of record. Putting fuzzy preferences into agent memory creates a second system of record that gets out of sync. |
| **Unnecessary MCP servers** | No iPix communication channel (Slack, Teams, WhatsApp) requires CopilotKit Channels. Operator chat already works within the app. |
| **Second orchestration layer** | Mastra already handles agent/workflow orchestration. Adding LangGraph, CrewAI, or another layer duplicates complexity without benefit. |
| **Silent autonomous writes** | Any tool that writes to DB without explicit HITL approval is a risk. All write tools (saveApprovedShootDraft, createBookingDraft, etc.) already have HITL gates. Do not remove these. |
| **Agent-controlled navigation that mutates production data** | Frontend tools like `navigateTo` are safe because they only redirect router. But if agent-controlled navigation were extended to directly mutate DB records without HITL, it would bypass approval gates. Keep navigation tools as router redirects only. |

## 11. iPix Workflow Examples

### Shoot Planning Workflow

```text
Brand DNA → agent creates shot list
        ↕ (shared state, if implemented)
Mastra sees latest shot-list state
        ↕
Agent adds three missing ecommerce shots
        ↕
UI updates without rebuilding conversation (if shared state)
HITL: operator approves deliverables → shot list → budget
        ↓
Mastra persists approved plan via saveApprovedShootDraft
```

**Current reality**: Steps 1, 4 work. Steps 2 (shared state), 3 (agent adds shots during HITL) are gaps.

### Asset DNA Review Workflow

```text
Asset uploaded → DNA agent evaluates (getAssetDnaEvidence)
        ↕
CopilotKit renders score/reasons (generative UI)
        ↕
Operator accepts/reshoots/overrides
        ↓
Decision logged via draftBulkAssetApproval (always draft pending HITL)
```

**Current reality**: All steps work. `draftBulkAssetApproval` always returns draft pending explicit approval — correct HITL pattern.

### Booking Workflow

```text
Agent suggests talent → booking proposal card
        ↕
Operator edits rate/date (HITL)
        ↕
HITL: operator approves/edits/rejects
        ↓
Booking FSM transition (createBookingDraft → saveApprovedShootDraft path)
```

**Current reality**: Agent suggests talent via creative-director. `draftBookingQuote` and `createBookingDraft` exist but booking flow not fully wired into CopilotKit chat. HITL pattern correct but flow not fully integrated.

### CRM Workflow

```text
Operator asks about client → agent reads visible CRM context
        ↕
Agent proposes next action (useFrontendTool navigateToCrm)
        ↕
HITL: approval before CRM mutation (draftFollowUp render tool)
        ↓
CRM write only after explicit operator approval
```

**Current reality**: `useAgentContext` exposes `activeBrandId`. `navigateToCrm` frontend tool works. `useCrmDraftFollowUpRender` renders editable draft with keep/discard actions. CRM writes go through HITL.

### Campaign Workflow

```text
Campaign brief ↔ shared state ↔ Creative Director agent
        ↕
Editable concept → approval → shoot generation
```

**Current reality**: `creative-director` agent handles `/app/campaigns`. `draftCampaignBrief` always returns draft pending approval. Shared state not implemented — concept edits require manual chat prompts.

## 12. Architecture Recommendation

### Current Architecture

```text
Next.js Operator UI (port 3002)
       │
       ├── deterministic React workspace
       │
       └── CopilotKit intelligence layer
                │
                ├── context (route + activeBrandId via useAgentContext)
                ├── chat (CopilotChat dock)
                ├── frontend tools (3: navigateTo, navigateToCrm, setActiveBrand)
                ├── Generative UI (1: draftFollowUp render tool)
                ├── shared state (NONE — gap)
                └── HITL (emitInterruptOutcome=false, 3 gates)
                           │
                           ▼
                        AG-UI
                           │
                           ▼
                        Mastra
                agents/workflows/tools
                       │
             ┌─────────┼─────────┐
             ▼         ▼         ▼
         Supabase   Cloudinary  Mercur
             │
             ▼
       canonical truth
```

### Recommended Architecture (Phase 1)

```text
Next.js Operator UI (port 3002)
       │
       ├── deterministic React workspace (unchanged)
       │
       └── CopilotKit intelligence layer (enhanced)
                │
                ├── context (route + activeBrandId + CRM context)
                ├── chat (CopilotChat dock, persistent threads)
                ├── frontend tools (8-10: + openShoot, selectAsset, applyFilter, openApproval, highlightObject)
                ├── Generative UI (5+: + generateShotList, assetDNA, bookingProposal, campaignBrief)
                ├── shared state (Phase 1: STATE_SNAPSHOT/STATE_DELTA for shoot list)
                └── HITL (emitInterruptOutcome=false, 3 gates, documented clone pattern)
                           │
                           ▼
                        AG-UI
                           │
                           ▼
                        Mastra
                agents/workflows/tools
                       │
             ┌─────────┼─────────┼─────────────┐
             ▼         ▼         ▼         ▼
         Supabase   Cloudinary  Mercur   Memory Store
             │           │           │         (Supabase-backed
             │           │           │            thread persistence)
       canonical truth   │           │         / Hyperdrive Postgres)
```

**Key principles preserved:**

- CopilotKit owns the agent-user experience
- Mastra owns agent/workflow orchestration
- Supabase owns deterministic business truth
- No silent autonomous writes — all DB writes go through HITL-gated tools
- Deterministic React workspace is primary UI; CopilotKit is the intelligence layer
