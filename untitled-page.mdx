**Production readiness: 60%** — functional for basic shoot planning and asset DNA review, but thread loss on reload and no shared state limit production use. HITL gates and security are solid.

## Top 3 Problems

| Rank | Issue | Impact |
| --- | --- | --- |
| **P0** | Threads die on page reload (in-memory only) | 🔴 Critical — operator loses conversation context |
| **P1** | No shared state between agent and UI | 🟠 High — agent can't see operator edits; UI can't see agent recommendations |
| **P2** | Only 1 generative UI tool (draftFollowUp) | 🟡 Medium — no shot list, asset DNA, booking, campaign renderers |

---

## Top 3 Recommendations

1. **Fix thread persistence** — Add Hyperdrive Postgres or Supabase-backed thread storage. Threads must survive page reloads.
2. **Add 3 proactive intelligence surfaces** — "3 shots missing for Amazon", "2 talent bookings need confirmation", "14 assets failed DNA".
3. **Expand frontend tools \+ generative UI** — Add 5 tools (openShoot, selectAsset, applyFilter, openApproval, highlightObject) and 4 `useRenderTool` registrations (generateShotList, assetDNA, bookingProposal, campaignBrief).

---

## Core vs Advanced

**CORE (should have now)**: AG-UI streaming, route-aware agent context, chat/headless intelligence panel, 3 frontend tools, Mastra backend tools, HITL, basic error/loading UX.

**ADVANCED (add where ROI exists)**: Shared state sync, generative UI expansion, proactive intelligence, persistent preference memory. Skip: A2UI, MCP Apps, Channels SDK, agent swarms.
